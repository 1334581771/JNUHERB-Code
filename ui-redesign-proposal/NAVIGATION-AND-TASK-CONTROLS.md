# 全局导航与网络药理学页的分工

根据本轮反馈，Analysis Mode 不再常驻全局侧栏。HTML 原型已将它移到网络药理学工作台内部，与原有输入及筛选说明放在一起。

## 全局侧栏

保留品牌、研究首页、网络药理学、AI 辅助辨证、配伍优化、分子对接及资源导航。首页继续展示实体插画、数据规模、模块入口和带图标的示例。

## 网络药理学页

依次展示：

1. Analysis Mode：🚀 Forward / 🎯 Reverse，直接显示当前方向的完整关系路径。
2. Query Entity Type：按模式选择中药、方剂、单体，或疾病、靶点。
3. 研究对象与 ID 类型：每行一个，提供具体格式示例与匹配提示。
4. 🎛️ Filters (optional)：蛋白限制、综合评分、疾病证据阈值等模式专属设置。
5. 🚀 Run Analysis：提交后显示实际任务状态。
6. 结果区：概览、实体、网络、富集及下游分析入口。

宽屏可把页内输入区与结果区按约 1:2 排列；无结果时先突出输入，小屏按输入、结果顺序纵向排列。无需再在全局侧栏复制一份模式或参数。

当前原型保留图标、方向切换及帮助说明；部分专属表单仍为共用示意，未接入 Python 计算。正式实现应将现有 st.sidebar.radio/selectbox/text_area/expander/button 移入网络药理学渲染函数的原生容器，保留业务 key、默认参数、pending_prefill、分析调度和结果状态。移动容器不应改变参数含义。

AI、配伍优化和分子对接只展示各自的输入与帮助，不复用网络药理学的正反向模式。模块切换应保存业务草稿；结果与最近提交的输入快照绑定。实施指南中此前建议在侧栏恢复 Analysis Mode 的内容由本文件取代。
