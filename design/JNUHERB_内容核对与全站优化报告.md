## 5. 源码中应先处理的问题

下列问题由当前实现推导；没有把静态检查说成已完成双用户线上压力测试。

### P0：结果正确性与用户隔离

1. **结果输出目录按运行隔离。** `streamlit_app.py:1520` 使用共享临时目录 `jnuherb_streamlit`。改为 `session_uuid/run_uuid`，每次运行记录输入、参数、数据版本、产物路径。文件锁限流不等于输出隔离。验收：两个会话并发运行不同案例，下载、图表、对接结果均不串用。
2. **API key 保持会话隔离。** `streamlit_app.py:2020` 把用户输入写入进程级 `os.environ`，与页面“只在会话中使用”的文字不一致。改为会话状态中保存并显式传入模型客户端；平台公共密钥单独由 secrets 读取。日志和产物不得保存 key。
3. **疾病解析的 ID 类型固定。** 疾病解析返回 Ensembl 蛋白 ID，但 `streamlit_app.py:1684` 附近仍将手动反向输入的 ID 类型选择传入 `from_proteins`。疾病分支应固定 Ensembl_ID，手动输入分支才使用用户所选类型。验收：手动分支切换为 gene_name 后，再切回疾病分析仍得到相同结果。
4. **同名疾病先消歧。** `query.py:200` 附近名称匹配可命中多个疾病 ID。应先通过 `get_diseases` 展示 ID、命名空间、靶标数并让用户选择，然后只按所选 ID 解析；不混合多个命名空间的目标后又标成其中一个疾病。
5. **重建实体与关系统计清单。** 修复成分–蛋白的目录外端点，定义去重、来源和版本规则。原始行数保留可追溯性；实体计数和分析图计数分别生成。

### P1：功能衔接、解释和执行方式

6. **AI 候选真正传入分析。** 当前按钮只写入 `forward_preset`（约 2107、2138 行），正文输入没有消费该值。按钮应写入稳定 ID、输入类别、来源案例，再导航到正确输入页并回填，用户确认后提交。
7. **Boost 标明比较基线。** `score.py:257–265` 用“所选组合内部最佳单项”作分母，公式为 `(组合分数/组合内最高单项分数−1)×100%`。不能描述为比全部候选中的最佳药物提高多少。图表加 `%`，同时展示组合内最佳与全候选最佳，避免误读。
8. **优化参数可见。** 当前网页默认重启 100 次、seed 138192，容量 c=10 没有作为完整界面参数暴露。增加“高级设置”，展示随机种子、次数、容量、目标和筛选范围，输出中保存参数。
9. **超时需真正中断执行。** `streamlit_app.py:1239` 的 ThreadPoolExecutor 上下文会在退出时等待线程；future 的超时不等于底层计算已停止。改成可终止子进程或任务队列，区分排队、运行、取消、失败、完成；不承诺线程超时能强制结束任务。
10. **按当前页面执行重计算。** 避免打开结果就同时触发所有富集。保留本地数据缓存，分析结果与富集按输入哈希和集合版本缓存；写文件操作不与共享路径缓存混用。
11. **对接结果随输入失效。** 新分析、新配体、新受体、box 或参数变化后清空或标记旧 `dock_result`，同时展示配体/受体 ID 与运行编号，避免旧姿态被误认为本次结果。
12. **跨平台锁。** 主脚本第 19 行无条件导入 `fcntl`，不适用于原生 Windows。改成跨平台进程/任务管理，并通过 `tempfile` 选择临时目录。

### P2：结果阅读与维护

13. Degree 页面标题由 PPI Network Degree 改为 Degree statistics：当前为异质网络度，不是蛋白互作网络度。
14. 网络超过阈值时展示可控的连通子图和全图下载，不直接让整个网络页不可用；固定布局随机种子。当前图展示药材、成分、蛋白三层，不把方剂和疾病图标误写成已经出现在分析网络中。
15. 富集图默认按调整后 P 值排序或明确排序选项，保留 raw P、adjusted P、Count、Gene ratio 与基因列表。GO 映射数按 BP/CC/MF 分别计算，不能把三者最大值当作并集大小。
16. 数据清单加入文件哈希与版本；SQLite `_meta` 的行数校验不足以保证内容没有变化。
17. README、API docstring、项目简介、手稿与主页同步更新；清理旧 578K 关系、七表等历史描述。保留版本历史，不用当前快照强行覆盖历史实验条件。

## 7. 页面视觉优化

首页保留绿色主视觉和四张功能卡，减少说明段落：标题一句、描述一句、输入→输出一行、明确按钮。长方法、When to use、参数说明放入 Guide 或展开区。

首页右侧使用方剂、药材、成分、蛋白、疾病五个科学示意图；疾病用**疾病条目卡＋医疗十字**表示，与其余四类并列。避免用一个器官代表所有疾病。图标采用统一 SVG，替代零散 emoji，便于缩放和统一配色。

数据计数放在独立统计带；数字下标明 Unique ingredients / Unique protein IDs / Disease terms，附“View counting definitions”。背景装饰不遮挡数字和功能按钮。

结果页采用固定结构：面包屑与标题 → 当前案例/运行状态 → 输入与保留计数 → 一张主要图 → 可搜索数据表 → 下载及解释。图表配可读的数值，不用纯装饰插图替代科学结果。

Try an example 打开案例选择弹窗，显示归脾汤与肺癌的输入、方向和参数；加载后进入对应结果总览，页面上始终保留当前案例标识。AI 示例进入症状输入页，不凭空展示一次尚未运行的模型答案。

对接页先完成受体、配体、box 与依赖检查；尚未运行时展示结构区空状态和步骤，成功后再显示真实分数、姿态和下载。

1. **路由**：使用 `st.Page`/`st.navigation` 组织页面。可以先使用稳定的分组导航；若需要与设计图完全相同的多层横向下拉，再做一个很小的导航组件，不依赖脆弱的全局 CSS 选择器。[Streamlit 官方导航文档](https://docs.streamlit.io/develop/api-reference/navigation/st.navigation)。
2. **输入提交**：把参数放进 `st.form`，提交后才启动分析，避免每次改一个控件就重跑业务计算。[官方 st.form 文档](https://docs.streamlit.io/develop/api-reference/execution-flow/st.form)。
3. **会话**：Session State 保存输入、运行编号、当前结果与候选选择；AI 候选传递稳定 ID；不要用全局环境变量承载用户 key。
4. **缓存**：`st.cache_data` 用于可序列化纯数据结果，键包含参数和数据版本；资源缓存仅用于适合跨会话共享且线程安全的资源。用户产物目录不作为共享缓存文件夹。[官方缓存说明](https://docs.streamlit.io/develop/concepts/architecture/caching)。
5. **惰性计算**：现有 tabs 默认会计算各标签内容。优先采用页面路由；如升级后使用 tabs 的状态跟踪，也要按活动状态显式条件执行。不能仅把代码包进 tab 就认定已实现按需加载。[官方 st.tabs 文档](https://docs.streamlit.io/develop/api-reference/layout/st.tabs)。
6. **界面**：原生容器、列、按钮、数据框优先；SVG 放本地 assets，固定纵横比。网络与三维结构通过组件承载；正文和操作按钮继续用原生控件，保证状态可控。

当前 pyproject 允许 Streamlit>=1.28.0，不代表最低版本支持所有新 API。实施前应选定并锁定经过项目验收的 Streamlit/Python/图组件版本；不要在声明的旧最低版本上直接加入最新 API。

### 8.2 实施顺序与验收

第一阶段：统计清单、疾病消歧与 ID 类型、key/输出隔离、旧结果失效。先保证相同输入稳定得到对应结果。

第二阶段：首页与输入页、结果总览、AI 候选继承、帮助页面。验收所有按钮都有明确去向；无结果时说明需要先完成哪个步骤。

第三阶段：富集、优化与对接的按需任务、进度、取消、下载及数据版本追踪。用三组本地复算案例做回归，再对安装了完整依赖的 Streamlit 环境做端到端和并发检查。

第四阶段：大数据表分页/服务端筛选、网络子图、移动端、键盘导航与颜色对比。性能目标应先在实际部署机器测基线，再规定，避免凭截图承诺运行速度。
